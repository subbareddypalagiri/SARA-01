🛡️ EVENT CAPTURING BYPASS - v1.2 FIX ✅

PROBLEM:
✨ button not appearing on gemini.google.com and other heavily controlled 
platforms that use event.stopPropagation() to block user interaction detection.

ROOT CAUSE:
Sites call e.stopPropagation() before our bubbling-phase listeners fire,
blocking us from detecting text selection.

SOLUTION:
Two surgical updates to content.js (NO changes to background.js or core logic):

1️⃣  EVENT CAPTURING BYPASS
    Changed event listeners from bubbling to capture phase:
    
    BEFORE: document.addEventListener('mouseup', lockSelection);
    AFTER:  document.addEventListener('mouseup', lockSelection, { capture: true });
    
    Result: Our listener fires BEFORE stopPropagation() can block it ✓

2️⃣  Z-INDEX SUPREMACY
    Added !important to all z-index values:
    
    BEFORE: z-index: 2147483647;
    AFTER:  z-index: 2147483647 !important;
    
    Result: Our UI guaranteed to appear above all site tooltips ✓

HOW IT WORKS:
═════════════════════════════════════════════════════════════════════════

  ↓

  ↓
We capture selection into lockedText/lockedRange ✓
  ↓

  ↓
But it's too late - we already got the selection! ✓

TECHNICAL DETAIL:
═════════════════════════════════════════════════════════════════════════

Event Phases:
- Capture phase: Events travel DOWN from document to target
- Bubbling phase: Events travel UP from target to document

Site Event Handlers:
  element.addEventListener('mouseup', handler);  // Default: bubbling
  element.addEventListener('mouseup', handler, true);  // Capture

When site calls e.stopPropagation():
  - Only stops further bubbling from that point
  - Doesn't affect events that already fired in capture phase

Our Fix:
  document.addEventListener('mouseup', lockSelection, { capture: true })
  - We listen in capture phase
  - We fire BEFORE site's bubbling listener
  - Site's stopPropagation() can't block us!

WHY Z-INDEX !important:
═════════════════════════════════════════════════════════════════════════

Z-Index Stacking:
- Gemini's tooltips: z-index 999999
- Our UI: z-index 2147483647 (max 32-bit int)
- But without !important, can still be overridden

With !important:
- z-index: 2147483647 !important; is HIGHEST specificity
- Nothing can override it (even Gemini's z-index: 999999999!)
- Guaranteed to appear on top
